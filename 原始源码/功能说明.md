# 虚拟主机CDN - 功能说明

## 产品概述
虚拟主机CDN 是一款专为虚拟主机环境设计的轻量级 CDN 源码。纯 PHP 原生实现，无需数据库、无需 Composer、无需额外服务器环境，一行代码即可植入任意现有 PHP 网站，实现页面缓存加速与资源分流。

---

## 一、核心功能

### 1. 页面整页缓存
- 首次访问页面时自动捕获输出并写入本地缓存文件
- 第二次及后续访问直接读取缓存输出，**原 PHP 脚本不再执行**
- 大幅降低源站 CPU 与数据库压力，提升页面响应速度

### 2. 智能资源分流（cdn_rules）
支持按正则规则对不同类型资源采取不同缓存策略：

| 动作 | 说明 | 适用场景 |
|------|------|----------|
| `cdn` | 走 CDN 缓存，命中则输出，未命中回源后缓存 | 图片、CSS、JS、HTML 等静态资源 |
| `origin` | 强制穿透回源，不缓存 | 动态接口、个人中心等实时性要求高的页面 |
| `bypass` | 直接放行，不缓存 | 后台管理、登录页等不应缓存的路径 |

**默认规则示例**：
- 图片（`.jpg/.png/.gif/.webp/.svg/.ico/.bmp`）→ 走 CDN 缓存
- 静态页面（`.html/.htm/.css/.js/.json/.xml/.txt`）→ 走 CDN 缓存
- 后台路径（`^/admin/`）→ 直接放行，不缓存

### 3. 原站继续在用
CDN 作为前置层部署，不修改原站任何代码。原站照常运行，CDN 只在前端拦截并缓存符合规则的请求。当访问压力增大时，只需启用 CDN 站点即可实现分流，无需改动原站。

### 4. 多节点 CDN + 地区智能调度

支持搭建**无限数量的 CDN 节点站点**，并根据访问者的 IP 归属地自动将请求调度到最近的节点。主站作为流量调度入口，各节点独立缓存和回源，互不干扰。

#### 4.1 工作原理

```
访问者 → 主站 CDN（cdn.php） → IP 地区识别 → 匹配最佳节点 → 302 重定向 → 节点 CDN → 缓存/回源
```

#### 4.2 节点配置

在 `config.php` 或 `nodes.json` 中配置多个节点，每个节点包含：

| 字段 | 说明 | 示例 |
|------|------|------|
| `id` | 节点唯一标识 | `node-bj` |
| `name` | 节点显示名称 | `北京节点` |
| `domain` | 节点域名（302 重定向目标） | `https://bj.cdn.example.com` |
| `origin` | 该节点的回源站点 | `https://origin-bj.example.com` |
| `regions` | 覆盖地区代码列表 | `['CN-BJ', 'CN']` 或 `['*']` |
| `weight` | 权重，数字越大优先级越高 | `100` |
| `enabled` | 是否启用 | `true` / `false` |

#### 4.3 地区匹配顺序

系统按以下顺序匹配节点：

1. **精确地区匹配**：如访问者地区为 `CN-BJ`，节点配置包含 `CN-BJ`
2. **国家级匹配**：如访问者地区为 `CN-BJ`，节点配置包含 `CN`
3. **兜底匹配**：节点配置包含 `*` 或 `--`，匹配所有地区
4. **权重排序**：同地区多个节点时，权重越高越优先

#### 4.4 启用多节点模式

在 `config.php` 中设置：

```php
'multi_node_enable' => true,
'main_domain'       => 'https://cdn.your-site.com',
```

然后通过后台 `/admin/nodes.php` 管理节点列表，支持添加、编辑、启用/禁用、删除节点。节点数据保存在 `nodes.json`，修改后立即生效。

#### 4.5 地区识别

- **在线模式**：配置 `region.api_url`（如 `https://ipapi.co/{ip}/json/`），通过外部 API 查询访问者 IP 归属地
- **离线模式**：使用 `region.local_map` 中的本地 IP 段映射，无需联网即可工作
- 未识别到地区时，使用兜底节点（配置了 `*` 的节点）

## 二、后台管理

访问 `/admin/` 进入 Web 管理后台，支持以下操作：

| 功能模块 | 说明 |
|----------|------|
| **仪表盘** | 查看总请求数、缓存命中数、回源数、命中率（百分比） |
| **多节点** | 管理 CDN 节点列表、地区映射、启用/禁用状态（`/admin/nodes.php`） |
| **命中率统计** | 按路径分片查看详细的命中/回源/绕过数据，辅助优化分流规则 |
| **清缓存** | 一键清空所有 `.cache` 缓存文件，支持主站单独清理或全部节点联动清理 |
| **插件开关** | 可视化开关启用/禁用已注册插件（UAFilter / CacheControl / Gzip），无需重启服务器 |

后台登录需设置密码（`admin_password`），防止未授权访问。

### 5. 主站一键清理缓存 + 节点联动清理

主站提供一键清理缓存功能，支持两种模式：

#### 5.1 仅清理主站
在后台 `/admin/cache.php` 点击"清理主站缓存"，仅删除本站 `runtime-cache/` 目录下的所有 `.cache` 文件，其他节点不受影响。

#### 5.2 清理所有节点（联动清理）
在后台点击"清理所有节点缓存"，系统会：
1. 先清理主站本地缓存
2. 通过 HTTP purge 接口，通知每个启用的 CDN 节点也清理本地缓存
3. 显示每个节点的清理成功/失败状态

#### 5.3 外部 HTTP Purge 接口
主站提供 HTTP purge 接口，可与发布系统、CMS 等集成，在内容更新后自动触发缓存清理：

```
GET {主站域名}/?purge=1&token={purge_token}&all_nodes=1
```

| 参数 | 说明 |
|------|------|
| `purge` | 固定值 `1` 或 `true`，表示触发清理 |
| `token` | 清理密钥，需与配置文件中的 `purge_token` 一致 |
| `all_nodes` | 可选，`1` 表示清理完主站后同时通知所有节点也清理，`0` 或不传表示仅清理主站 |

**示例**：
```bash
curl "https://cdn.your-site.com/?purge=1&token=abc123&all_nodes=1"
```

**安全提示**：请在配置文件中设置 `purge_token` 为强随机字符串，防止未授权调用清理接口。若 `purge_token` 为空，远程 purge 接口将被禁用。

### 6. 节点健康检查

系统自动探测每个 CDN 节点的可用性，并在后台显示在线/离线状态。

#### 6.1 检测机制
- 使用 HTTP HEAD 请求探测节点域名，超时设置为 5 秒
- 返回 200-399 状态码判定为**在线**，否则为**离线**
- 记录响应时间、检查次数、失败次数
- 结果按日期保存在 `health_checks/` 目录

#### 6.2 离线节点自动跳过
当节点处于离线状态时：
- **多节点调度**：访问者不会被重定向到离线节点
- **缓存清理**：一键清理时会跳过离线节点，避免无效请求
- **后台显示**：节点列表和健康检查页面显示离线状态及错误信息

#### 6.3 后台入口
访问 `/admin/health.php` 查看所有节点的健康状态，支持手动重新检测。

### 7. 节点间缓存同步

当主站或任一节点执行缓存清理时，系统支持联动通知其他节点也清理本地缓存，确保全网缓存一致。

#### 7.1 联动清理流程
1. 管理员在主站后台点击"清理所有节点缓存"
2. 主站先清理本地缓存
3. 主站通过 HTTP purge 接口，依次通知每个启用的 CDN 节点
4. 每个节点收到请求后验证 token，清理本地缓存，返回结果
5. 后台显示每个节点的清理成功/失败状态

#### 7.2 外部触发联动清理
通过 HTTP purge 接口并设置 `all_nodes=1` 可实现同效：

```bash
curl "https://cdn.your-site.com/?purge=1&token=abc123&all_nodes=1"
```

#### 7.3 离线节点处理
如果某个节点处于离线状态，联动清理时会自动跳过该节点，并在后台显示跳过原因，避免影响整体操作。

### 8. 清理日志审计

系统记录每次缓存清理操作，支持事后追溯和审计。

#### 8.1 记录内容
每条清理日志包含：
- 操作时间
- 操作者（后台 / 远程 API）
- 清理范围（仅主站 / 全部节点）
- 主站删除文件数
- 清理令牌（脱敏显示后4位）
- 各节点的清理结果（成功/失败/跳过及原因）

#### 8.2 后台查看
访问 `/admin/purge_logs.php` 查看清理历史记录，支持查看最近 100 条记录和今日统计摘要。

#### 8.3 日志存储
日志按日期保存在 `purge_logs/` 目录，格式为 JSON，最多保留最近 500 条，无需数据库。

### 9. 缓存预热同步

清理缓存后，系统自动将配置的热门URL预热到各CDN节点，避免首次访问回源造成压力。

#### 9.1 预热机制
- 清理缓存后，自动向每个在线节点发送预热请求（带 `__cdn_warm=1` 标记）
- 节点收到请求后回源抓取并缓存内容，后续访问直接命中
- 离线节点自动跳过，不影响整体预热

#### 9.2 预热URL配置
访问 `/admin/cache_warm.php` 管理预热URL列表。每行一个URL，格式：`URL|名称`（名称可选）。

示例：
```
https://cdn.example.com/index.php|首页
https://cdn.example.com/img/banner.jpg|首页横幅
```

#### 9.3 手动预热
后台提供"立即预热所有节点"按钮，可随时触发全量预热，适合内容发布后立即生效。

### 10. 清理日志导出

系统支持将清理审计日志导出为 CSV 或 JSON 文件，便合规审计和存档。

#### 10.1 导出入口
访问 `/admin/purge_logs.php`，点击"导出CSV"或"导出JSON"按钮。

#### 10.2 导出内容
每条记录包含：时间、操作者、范围、主站删除数、令牌、节点ID、节点名称、节点状态、节点消息。

#### 10.3 外部接口
可通过 HTTP 接口直接导出：
```bash
# 导出CSV
curl "https://cdn.your-site.com/admin/action.php?do=purge_log_export&format=csv" > purge_logs.csv

# 导出JSON
curl "https://cdn.your-site.com/admin/action.php?do=purge_log_export&format=json" > purge_logs.json
```

### 11. 多节点负载均衡调度

当同地区有多个可用节点时，系统根据配置的负载均衡策略动态选择最佳节点进行302重定向。

#### 11.1 支持的策略
| 策略 | 说明 |
|------|------|
| `least_rt` | 最小响应时间优先（响应快的节点被优先选中，默认） |
| `round_robin` | 轮询（同权重节点轮流选中） |
| `weighted` | 加权随机（按权重比例随机选中） |

#### 11.2 配置
在 `config.php` 中设置：
```php
'lb_strategy' => 'least_rt',    // 负载均衡策略
'lb_health_threshold' => 3,     // 健康检查阈值，连续失败超过此次数的节点暂时剔除
```

#### 11.3 调度逻辑
1. 检测访问者地区
2. 匹配该地区的所有启用且在线的节点
3. 根据负载均衡策略选择最佳节点
4. 302重定向到选定节点
5. 响应头中包含 `X-CDN-LB-Strategy` 标记当前策略

## 三、内置插件

| 插件 | 作用 |
|------|------|
| **UAFilter** | 识别爬虫/命令行工具 User-Agent，添加 `X-CDN-Bypass: 1` 标记，便于监控与分析 |
| **CacheControl** | 自动注入 `Cache-Control` 响应头，并在 `X-SimpleCDN: HIT0/1` 中标记本次请求是回源（0）还是命中缓存（1） |
| **Gzip** | 客户端支持时对输出内容进行 gzip 压缩，减少传输流量；自动跳过已开启服务器压缩或不支持的场景 |

## 四、技术特点

| 特性 | 说明 |
|------|------|
| **零数据库** | 缓存与统计均以本地文件形式存储，无需 MySQL/SQLite |
| **零 Composer** | 纯 PHP 原生代码，无第三方依赖，直接上传即用 |
| **原子写入** | 缓存文件写入采用临时文件 + 重命名方式，避免并发写入损坏 |
| **过期控制** | 缓存文件按 TTL 过期自动失效，支持按需设置不同时效 |
| **UA 分片缓存** | 可按移动端 / PC 端分别缓存，避免响应式页面错位 |
| **查询串分片** | 带不同参数的 URL 缓存键不同，避免 `?id=1` 与 `?id=2` 内容串站 |
| **回源直连** | 默认不继承服务器代理环境变量，回源请求直达源站，避免中间层劫持 |
| **逐跳头过滤** | 回源时自动剔除 `Host` / `Date` / `Content-Length` 等逐跳响应头，避免重复头部 |

## 五、适用场景

1. **虚拟主机加速**：无法安装 Node.js / Redis / Nginx 缓存模块的共享主机
2. **静态资源分流**：图片、CSS、JS 等静态文件走 CDN 缓存，减轻源站带宽
3. **动态站点前置缓存**：博客、企业官网等内容相对固定的站点，整页缓存提升打开速度
4. **原站压力分流**：访问量突增时，先部署 CDN 前置层，热点内容直接命中缓存，不回源

---

## 六、部署要求

- **Web 服务器**：Apache（支持 `.htaccess`）或 Nginx（需手动配置 rewrite）
- **PHP 版本**：5.6 / 7.x / 8.x 均可，推荐 7.4+
- **PHP 扩展**：curl（必需，用于回源抓取）
- **目录权限**：`runtime-cache/` 与 `stats/` 需对 Web 运行用户可写
